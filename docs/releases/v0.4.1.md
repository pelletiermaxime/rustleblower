Rustleblower v0.4.1 updates the native UI, improves large blocklist downloads and
adds a development hot reload workflow.

- Double-click a column's resize edge in **History**, **Live** or **Data usage**
  to fit its header and currently loaded rows. Column widths remain bounded.
- Large blocklist downloads use buffered writes and yield during normalization,
  keeping subscription requests and cancellation responsive. Failed downloads
  still preserve the last usable blocklist.
- Update GPUI Kit to 0.8.0 and the GPUI Fast backend to 0.1.10.
- Add a documented hot reload launcher for developers, with a separate local
  socket and data directory by default. See the
  [development guide](https://github.com/pelletiermaxime/rustleblower/blob/v0.4.1/docs/development.md).
- Replace a timing-dependent subscription test with a deterministic check that
  permission replies remain responsive while a real subscription transaction
  holds the SQLite writer lock. The original reply deadlines remain in place.

**Linux x86-64.** Verify downloads using `SHA256SUMS`. Packages are built on
Ubuntu 24.04 and require glibc 2.39 or newer, an installed font, a compatible
graphics driver and a Wayland or X11 desktop. Without FUSE, run the AppImage with
`--appimage-extract-and-run`.

The AppImage, Debian package and tar archive include the experimental data usage
collector introduced in v0.4.0. See the
[data usage guide](https://github.com/pelletiermaxime/rustleblower/blob/v0.4.1/docs/data-usage.md)
for authorization, kernel requirements and measurement limits.

Install the OpenSnitch daemon separately and run Rustleblower as your desktop
user. Quit opensnitch-ui before using the default local socket;
Rustleblower refuses to replace an existing `/tmp/osui.sock`. The daemon keeps
ownership of interception, enforcement and saved rules.
