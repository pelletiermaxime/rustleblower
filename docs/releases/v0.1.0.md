Rustleblower’s first Linux development release: a native Rust + GPUI Kit frontend
for the existing OpenSnitch daemon. The interface is early and will be redesigned;
this release is a functional starting point, with incomplete opensnitch-ui parity.

- Review connections in a separate permission window with Allow, Deny or Reject,
  temporary/permanent decisions, matching conditions and saved popup defaults.
- Browse application rules and manually allow an application after a missed prompt.
  Create, edit, duplicate, import/export and apply reviewed bulk changes, with
  daemon confirmation before displaying success.
- Search disk-backed connection history, inspect details, filter/sort columns and
  export CSV or JSON. Browse daemon-reported statistics independently of history.
- Select connected nodes, control interception and review/apply daemon preferences
  with a changed-field preview and complete JSON editor.
- Keep history, pages and pending work bounded while permission decisions remain
  independent of telemetry ingestion and disk writes.

**Linux x86-64 only.** Built on Ubuntu 24.04; requires glibc 2.39 or newer, an
installed font, a supported graphics driver and a Wayland or X11 desktop. Install
OpenSnitch’s daemon separately. Compatibility currently targets OpenSnitch 1.7.2.
Rustleblower does not install or replace the daemon, and does not import the old
UI’s history. The daemon continues to own firewall enforcement and saved policy.

Download the AppImage for a standalone launch, the `.deb` for Ubuntu/Debian
installation, or the tar archive for a manual installation. `SHA256SUMS` covers
all three packages. The AppImage still uses the host glibc and graphics stack;
without FUSE, use `--appimage-extract-and-run`.

Quit opensnitch-ui before launching Rustleblower so it releases `/tmp/osui.sock`.
Rustleblower refuses to replace an existing socket. Run it as your desktop user.
Closing the window minimizes it; use **Quit Rustleblower** to exit.

Remote TCP/TLS, system-firewall editing, tray/autostart integration, live resource
monitors and other parity work remain pending. The interface and packaging need
broader distribution testing. Automated tests cover isolated protocol/storage and
GPU/input journeys; they do not establish enforcement by every real daemon or a
memory improvement over the Qt UI.
